# 2. Regolamento AUTOREVOLE

Usare il regolamento originale già adottato per la nuova app.

## 2.1 Qualifica

### Pole Position

| Posizione ufficiale | Punti |
| ------------------- | ----: |
| P1                  |    +5 |
| P2                  |    +2 |
| Altra posizione     |     0 |

### Tempo Pole

La funzione autorevole è:

```text
public.calculate_qualifying_time_points(p_predicted, p_actual)
```

Regole:

| Errore                   | Punti |
| ------------------------ | ----: |
| `abs(errore) <= 0.010 s` |    10 |
| `> 0.010 s` e `<= 0.1%`  |     5 |
| `> 0.1%` e `<= 0.25%`    |     3 |
| `> 0.25%` e `<= 0.5%`    |     1 |
| oltre                    |     0 |

I limiti sono inclusivi.

Il controllo:

```text
abs(predicted - actual) <= 0.010
```

deve avere precedenza rispetto alle fasce percentuali.

Tempo nullo, non valido o tempo ufficiale non positivo:

```text
0 punti
```

Non duplicare questa logica dentro `score_prediction` se la RPC esistente può essere utilizzata correttamente.

# 5. Bonus Gara — CUMULABILI

Questo è un requisito fondamentale.

I bonus Gara devono essere **cumulabili**.

## Bonus ordine esatto

Se i cinque piloti sono corretti **e nell'ordine esatto**:

```text
+5 punti
```

## Bonus Top 5

Se tutti i cinque piloti pronosticati terminano nella Top 5:

```text
+2 punti
```

### Cumulabilità

Se l'ordine è completamente corretto:

```text
+5 ordine
+2 Top 5
= +7 punti bonus
```

NON utilizzare la logica alternativa:

```text
if ordine_esatto
    +5
else if Top5
    +2
```

perché renderebbe i bonus non cumulabili.

Devono invece essere calcolati separatamente:

```text
bonus_order = 5 se ordine esatto
bonus_top5 = 2 se tutti e cinque nella Top 5
total_bonus = bonus_order + bonus_top5
```

# 6. Bonus OUT

Mantenere il regolamento originale:

```text
+2 punti
```

Il bonus viene assegnato quando il pilota indicato come OUT non completa la Gara secondo la semantica prevista dal regolamento originale.

Verificare la gestione degli status effettivamente disponibili nel database.

Devono essere analizzati almeno:

* `CLASSIFIED`
* `NOT_CLASSIFIED`
* `NOT_IN_RESULT`
* `DNF`
* `DNS`
* `DSQ`
* eventuale `OUT`

Non assumere automaticamente che tutti gli status siano equivalenti senza verificare come vengono rappresentati nei risultati ufficiali.

Il pilota OUT deve essere distinto dai cinque piloti pronosticati per la Gara.

Se la struttura del database impedisce questa distinzione, documentare il problema anziché inventare una soluzione.
