# Task 41 — Debug caricamento punteggi partecipanti nella Lega

## PROBLEMA

Nella pagina di dettaglio della lega `/leghe/:leagueId`:

* Nicholas visualizza correttamente i propri punteggi GP;
* gli altri partecipanti della stessa lega non visualizzano i propri pronostici/punteggi;
* la UI mostra quindi correttamente la struttura, ma i dati degli altri partecipanti risultano vuoti.

Il problema è da trattare come **bug di data loading / mapping**, NON come problema di design.

## OBIETTIVO

Individuare perché i punteggi/prediction degli altri membri della lega non vengono associati correttamente ai rispettivi partecipanti.

NON modificare il database.

NON modificare i punteggi.

NON modificare lo scoring.

NON creare nuove prediction.

---

# 1. PRIMA COSA DA VERIFICARE

Analizza il codice attuale della pagina:

```text
/leghe/:leagueId
```

e ricostruisci esattamente questo flusso:

```text
league
  ↓
league_members
  ↓
partecipanti
  ↓
prediction / prediction_entries
  ↓
GP
  ↓
punteggio
  ↓
participant × GP
```

Individua esattamente dove i dati vengono persi.

---

# 2. VERIFICA DEI PARTECIPANTI

La pagina deve prima recuperare tutti i membri della lega tramite:

```text
league_id
```

Verifica che vengano recuperati TUTTI i membri di `TEST01`.

Non usare l'utente corrente come filtro.

Non filtrare i partecipanti sulla base di:

```text
auth.uid()
```

ad eccezione del normale controllo che l'utente corrente appartenga alla lega.

Il controllo deve essere:

```text
utente corrente appartiene alla lega?
    ↓
SI → carica tutti i membri della lega
NO → accesso negato
```

NON:

```text
utente corrente appartiene alla lega?
    ↓
SI → carica solo i dati dell'utente corrente
```

---

# 3. VERIFICA DELLE PREDICTION

Verifica come vengono caricate le prediction.

Le prediction devono essere associate agli utenti tramite:

```text
predictions.user_id
```

e al GP tramite:

```text
predictions.grand_prix_id
```

NON assumere che `prediction_entries` contenga direttamente `user_id`.

La relazione corretta è:

```text
league_members.user_id
        ↓
predictions.user_id
        ↓
predictions.id
        ↓
prediction_entries.prediction_id
```

e:

```text
predictions.grand_prix_id
        ↓
grand_prix.id
```

---

# 4. POSSIBILE BUG DA CERCARE

Cerca esplicitamente codice simile a:

```text
predictions.filter(...)
```

o:

```text
prediction.user_id === currentUser.id
```

o:

```text
user_id === currentUserId
```

o:

```text
participantIds.includes(...)
```

o qualsiasi filtro che utilizzi l'utente autenticato dopo aver già verificato l'appartenenza alla lega.

Questo tipo di filtro NON deve eliminare le prediction degli altri membri.

# 7. NON CAMBIARE LA QUERY SENZA CAPIRE IL BUG

Prima individua il punto preciso in cui i dati vengono persi.

Se la query attuale è già corretta e restituisce tutti i partecipanti/prediction, correggi solamente il mapping frontend.

Se invece la query applica erroneamente un filtro sull'utente corrente, rimuovi SOLO quel filtro.

Non introdurre query aggiuntive se non necessarie.

---

# 8. STRUTTURA DATI ATTESA

La struttura finale utilizzata dalla UI deve concettualmente essere:

```text
participants = [
  {
    userId: "...",
    name: "Nicholas",
    scores: {
      thailand: 21,
      brazil: 25,
      ...
    }
  },
  {
    userId: "...",
    name: "Alessandro",
    scores: {
      brazil: 18,
      ...
    }
  },
  ...
]
```

Ogni score deve essere indicizzato almeno per:

```text
user_id + grand_prix_id
```

NON solamente:

```text
grand_prix_id
```

e NON solamente:

```text
current_user_id + grand_prix_id
```
